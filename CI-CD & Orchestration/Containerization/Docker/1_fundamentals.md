# Docker Fundamentals

## What is Docker?
Docker is a platform that packages your application and all its dependencies into a standardized unit called a **container**. Think of it like a lightweight, portable box that contains everything your app needs to run — code, runtime, libraries, and system tools.

## Why Docker?
| Problem Without Docker | Solution With Docker |
| :--- | :--- |
| "It works on my machine!" | Same environment everywhere |
| Installing dependencies manually | All deps bundled in the image |
| Conflicting software versions | Each container is isolated |
| Slow VM-based deployments | Containers start in seconds |
| Complex server setup | One command: `docker run` |

## Key Terminology

### Image
A **read-only template** containing instructions for creating a container. Think of it as a blueprint or a class in OOP. Images are built from a `Dockerfile`.

### Container
A **running instance** of an image. Think of it as an object created from the class. You can have multiple containers running from the same image.

### Dockerfile
A **text file** with instructions for building a Docker image. Each instruction creates a layer in the image.

### Registry
A **storage and distribution system** for Docker images. Docker Hub is the default public registry (like npm for Node packages).

### Volume
A mechanism for **persisting data** generated by and used by Docker containers. Without volumes, data inside a container is lost when the container stops.

### Network
Docker creates virtual networks for containers to **communicate with each other**. Containers on the same network can reference each other by name.

## The Docker Architecture

```
┌─────────────────────────────────────────────┐
│                Docker Client                │

                   │ REST API

│              Docker Daemon                  │

│     networks, volumes)                      │

       │           │              │
   ┌───▼──┐   ┌───▼──┐      ┌───▼───┐

   │  A   │   │  B   │      │  C    │

   └──────┘   └──────┘      └───────┘
```

## Container vs. Virtual Machine

```
   Container                       Virtual Machine
┌──────────────┐              ┌──────────────┐
│   App A      │              │   App A      │
│   Libs/Bins  │              │   Libs/Bins  │
├──────────────┤              │   Guest OS   │
│   App B      │              ├──────────────┤
│   Libs/Bins  │              │   App B      │
├══════════════┤              │   Libs/Bins  │
│ Docker Engine│              │   Guest OS   │
├══════════════┤              ├══════════════┤
│   Host OS    │              │  Hypervisor  │
├══════════════┤              ├══════════════┤
│  Hardware    │              │  Hardware    │
└──────────────┘              └──────────────┘

Shares the host kernel           Each VM runs a full OS
Starts in seconds                Starts in minutes
Uses MBs of RAM                  Uses GBs of RAM
```
