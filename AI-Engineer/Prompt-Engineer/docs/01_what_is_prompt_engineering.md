# 01. What is Prompt Engineering?

Prompt Engineering is the discipline of designing, structuring, and optimizing the text instructions (prompts) given to a Large Language Model (LLM) to control its behavior and maximize the quality of its output.

---

## 1. Why Does It Matter?

The same model can produce wildly different results depending on how you ask. Prompt engineering is the **highest ROI skill** in AI because:

- **Zero cost**: No GPUs, no training data, no fine-tuning required.
- **Instant feedback**: You can iterate in seconds.
- **Universal**: Works across all models (GPT, Claude, Gemini, Llama, Mistral).
- **Composable**: Good prompts can be chained, templated, and reused.

| Approach | Cost | Time to Implement | Skill Required |
| :--- | :--- | :--- | :--- |
| **Prompt Engineering** | Free | Minutes | Low |
| **RAG** | Medium | Days | Medium |
| **Fine-tuning** | High | Days–Weeks | High |
| **Training from Scratch** | Very High | Months | Expert |

> **Rule of Thumb**: Always start with prompt engineering. Only escalate to RAG or fine-tuning if prompting alone cannot solve the problem.

---

## 2. How LLMs Process Prompts

Understanding how a model "reads" your prompt is critical to writing better ones.

### Tokenization
LLMs don't see words — they see **tokens**. A token is roughly ¾ of a word.

```
"Prompt engineering is important" → ["Prompt", " engineering", " is", " important"]
```

- Shorter prompts = fewer tokens = cheaper and faster.
- But clarity should **never** be sacrificed for brevity.

### Autoregressive Generation
LLMs generate text **one token at a time**, predicting the next most probable token based on all previous tokens. Your prompt is the "seed" that determines the probability distribution for every subsequent word.

```
Your Prompt → [Token 1] → [Token 2] → [Token 3] → ...
              ↑            ↑            ↑
          Most probable  Next most    And so on...
          given prompt   probable
```

### The Context Window
The **context window** is the total number of tokens a model can process at once (prompt + response combined).

| Model | Context Window |
| :--- | :--- |
| GPT-4o | 128K tokens |
| Claude 3.5 Sonnet | 200K tokens |
| Gemini 2.5 Pro | 1M tokens |
| Llama 3.1 405B | 128K tokens |

---

## 3. The Spectrum of Prompt Engineering

Prompt engineering ranges from casual one-liners to complex, multi-step systems.

```
Simple Question          →  "What is Python?"
Instruction              →  "Explain Python in 3 bullet points for a beginner."
Structured Prompt        →  System Prompt + Role + Task + Format + Constraints
Prompt Chain             →  Prompt A → Output A → Prompt B (uses Output A) → Final Output
Agentic Prompt           →  Reasoning loop with tool calls, self-reflection, and memory
```

## 4. Key Terminology

| Term | Definition |
| :--- | :--- |
| **Prompt** | The text input sent to an LLM. |
| **Completion** | The text output generated by the LLM. |
| **System Prompt** | A special instruction that sets the model's persona and rules (not all APIs expose this). |
| **Temperature** | Controls randomness. `0` = deterministic, `1` = creative. |
| **Top-p** | Nucleus sampling — limits token selection to the top `p%` of probability mass. |
| **Max Tokens** | The maximum number of tokens the model will generate in its response. |
| **Stop Sequence** | A string that tells the model to stop generating (e.g., `\n\n` or `---`). |
| **Hallucination** | When the model generates plausible-sounding but factually incorrect information. |
| **Grounding** | Providing the model with factual data (via RAG or context) to reduce hallucinations. |
