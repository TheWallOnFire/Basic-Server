# 02. Manual Testing

Manual testing is the foundation of QA. Before automating, you must understand how to test effectively by hand.

## 1. Test Cases
A test case is a set of conditions to verify a feature works correctly.
- **Test Case ID**: Unique identifier.
- **Preconditions**: What must be true before testing.
- **Steps**: Step-by-step instructions.
- **Expected Result**: What *should* happen.
- **Actual Result**: What *actually* happened.
- **Status**: Pass / Fail / Blocked.

## 2. Test Plans & Test Suites
- **Test Plan**: A document outlining the scope, approach, resources, and schedule of testing.
- **Test Suite**: A collection of related test cases grouped by feature or module.

## 3. Exploratory Testing
- Unscripted, creative testing based on the tester's intuition and experience.
- **Session-Based Testing**: Timeboxed exploration with a charter (goal).
- Great for finding edge cases that scripted tests miss.

## 4. Bug Reporting
A good bug report includes:
- **Title**: Clear, concise summary.
- **Severity**: Critical / Major / Minor / Trivial.
- **Priority**: How urgently it needs fixing.
- **Steps to Reproduce**: Exact sequence to trigger the bug.
- **Expected vs. Actual**: What went wrong.
- **Environment**: Browser, OS, device, version.
- **Screenshots / Videos**: Visual proof.

## 5. Tools
- **Jira**: Industry standard for bug tracking.
- **TestRail / Zephyr**: Test case management.
- **Notion / Confluence**: Documentation.
